# محدوده و مجوز

Scope (قلمرو جداسازی داده) و Actor (عامل اجرا) اجباری‌اند. مسیر خودکار ContextFactory هویت را فقط از UserResolver ثبت‌شده میزبان می‌خواند؛ نبود کاربر خطاست. با Branch (شعبه) فعال Scope دقیقاً branch:<شناسه> است؛ در حالت غیرفعال پیش‌فرض default دارد؛ نگاشت اطلاعات قبلی باید عمداً حفظ شود. قابلیت‌ها را از سیاست معتبر سرور بسازید؛ [اتصال Resolverها](../01-getting-started/resolvers.md) مرجع تنظیم و جلوگیری از نشت زمینه است.

مجوز باید قبل از Query، Count، Facet و Export اعمال شود. `SubjectHandler::query` پرس‌وجوی محدودشدهٔ فعلی را برمی‌گرداند؛ هسته شرط Scope را اضافه می‌کند. guard و بازپخش Journal نیز دسترسی فعلی را بررسی می‌کنند.

گیرندهٔ یادآور مستقل از سازنده و مسئول Ticket است. پیش‌فرض فقط خود کاربر را می‌پذیرد. `reminder.view_others` جایگزین مجوز Subject نیست؛ محدودیت Provider و Handler هر دو اجرا می‌شوند. هسته برای بررسی گیرنده، قابلیت‌های سازنده را کپی و جعل هویت نمی‌کند.

[TicketMessageAccess](../../examples/Ticketing/TicketMessageAccess.php) فقط یادداشت داخلی با منشأ دپارتمان مجاز را می‌خواند. منشأ نامعلوم پنهان می‌ماند. مسیرهای قدیمی میزبان که این سیاست را دور می‌زنند باید در برنامهٔ مصرف‌کننده اصلاح یا بسته شوند.

Audit (ردپای تغییر) متن خصوصی، نتیجه، رمز و توکن را منتقل نمی‌کند. رد انتقال در `tm_security_decisions` ثبت می‌شود. عملیات ناموفق نباید وضعیت نیمه‌کاره بسازد.
