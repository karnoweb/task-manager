# TM-168 — رد قرارداد و بازگشت برای اصلاح

این آزمون مستقل مربوط به فاز ۳ است؛ نتیجهٔ نهایی فاز ۷ محسوب نمی‌شود.

پیش‌نیاز: پایگاه‌دادهٔ اختصاصی آزمون، میزبان آزمایشی با مجوز صریح، ساعت کنترل‌شده و دو مسیر فروش و قرارداد. دادهٔ محرمانه در میزبان می‌ماند.

مراحل و انتظار دقیق در بدنهٔ اجرایی زیر مشخص است. هر فرمان با نسخه و شناسهٔ عملیات اجرا می‌شود؛ نتیجه، وضعیت، تاریخچه یا تعداد اثرها بررسی می‌شود. شکست هر انتظار آزمون را ناموفق می‌کند.

اجرا: `php vendor/bin/phpunit --filter TM168Test`. آزمون هم‌زمانی TM-175 فقط روی PostgreSQL واقعی اجرا می‌شود؛ کنارگذاری آن در SQLite قبولی نیست.

```php
public function test_tm168(): void
    {
        $policy = $this->returnPolicy(); $policy['returns']['rejected'] = ['transition' => 'correct', 'reason_code' => 'invalid'];
        [$h, $origin, $destination] = $this->delegateFixture(false, $policy);
        $this->instances()->transition($this->manager(), $destination['instance_key'], 1, 'reject', 'reject', ['reason_code' => 'invalid']);
        $r = $this->handoffs()->settle($this->manager(), $h['handoff_key'], 1, 'return');
        self::assertSame('resolved', $r['status']); self::assertSame('rejected', $r['outcome']);
        $result = $this->instances()->get($this->manager(), $origin['instance_key']);
        self::assertSame('new', $result['current_state_key']); self::assertSame('active', $result['lifecycle']);
        self::assertStringContainsString('invalid', DB::table('tm_audit_events')->where('aggregate_key', $origin['instance_key'])->where('action', 'instance_transitioned')->value('payload'));
    }
```

فایل اجرایی: `tests/Scenarios/TM168Test.php`. پشتیبان داده و سیاست: `tests/HandoffTestCase.php`. برای آزمون حدنصاب، سه مقصد مستقل با سیاست اعلام‌شده ساخته می‌شود؛ برای مسئول، هر سه حالت با دادهٔ جداگانه اجرا می‌شود.
