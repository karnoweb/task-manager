# Host-owned subject routes and remote Saga checkpoint

The core has no CRM or Ticket table dependency. Hosts register immutable route references in `SubjectRouteRegistry`; class names and executable callbacks are never read from stored data. Local and remote contracts explicitly have different transaction semantics.

`TaskManager.routes()` exposes `LocalRouteService.move/spawn`. A `LocalSubjectRouter` identifies the exact Laravel Connection object used by the owner service. A different object is rejected before any owner write; an identical DSN is insufficient. The owner service performs department changes or creates the new business subject, while InstanceService performs authorized workflow/pipeline changes. Source, target, case links, conversion lineage, history and outbox use the same real transaction boundary. Host implementations must not commit, switch connections, send network requests or emit external effects inside this local contract.

Move retains the same public subject and instance identities and uses an explicit versioned pipeline preview. Spawn creates a distinct host-owned subject, starts its authorized process, executes the configured source transition and links both to one case. No source private messages, attachments or entire model payload are copied. Per-subject SQL authorization still filters case history. A later workflow/host veto rolls back the actual owner-service writes and all package writes together.

`TaskManager.sagas()` exposes `ExternalSagaService.begin/get/execute/run/repair` for a remote owner. Its `RemoteSubjectRouter` must provide read-only prepare, durably idempotent create, durable receipt lookup and idempotent compensation. The registry reference should be versioned when behavior changes. The default registry is empty and fails closed. Export is restricted to explicitly prepared summary/customer/public-reference fields. Generic source private content cannot be exported through this API. Read results exclude prepared payloads and raw receipts; audit events contain control metadata only.

Begin reserves one active Saga per source and commits `pending_external` plus the outbox request. It does not report source conversion or remote success. Execute refuses an existing local transaction, rechecks current source access/version, then calls the remote owner using the stable key `external-create:<saga UUID>` outside the local transaction. A lost response leaves a pending request; retry uses the same key. Only a valid same-scope receipt permits the local source transition and external case link. The package stores the remote process reference and does not pretend it is a locally queryable workflow instance or a globally atomic transaction.

If local confirmation fails after remote creation, `compensating` is durable before the remote compensation request. Success becomes `compensated`; failure becomes `needs_manual_repair`. A changed source after a lost acknowledgement enters manual review instead of guessing whether a remote effect exists. Explicit versioned repair requires `saga.repair`, performs durable owner receipt lookup, then compensates or confirms the absence of a remote effect. An unresolved review keeps the source reservation. Bounded scoped run resumes pending requests/compensation; review items require an explicit repair action. Original source state is never overwritten by repair.

Tests use a real separate SQLite file for the remote owner, even when the package uses PostgreSQL. They prove the remote row survives a local rollback, a lost response does not create a duplicate, compensation/manual repair is explicit, private exports/cross-scope receipts fail closed, permission revocation blocks external execution, and two real workers produce one remote row and one local confirmation. These are executable integration-contract fixtures; installed commercial CRM integration, MySQL and production transport resilience still require later acceptance. The complete phase-three/phase-seven gates are not passed by these subsets.
