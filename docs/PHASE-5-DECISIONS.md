# Phase 5 schema, contracts and decisions

Migrations 000020..000025 add scheduling, typed fields/query metadata, automation/integration receipts, exports and report projections. New owned identifiers use the exact-identifier collation helper. Internal relationships use actual foreign keys; webhook receipts reference external event IDs intentionally. Export/report item membership uses Task/Instance foreign keys and provides fresh permission checks without loading all IDs into PHP.

## Time and calendar

`starts_at` / `ends_at` are UTC half-open spans; `due_at` is independent. All-day data additionally preserves local start/end DATE values; display never obtains an extra day by converting the exclusive end into an inclusive timestamp. `LocalTime` enumerates valid offsets. Nonexistent input times reject; ambiguous inputs require reject/earliest/latest. Recurrence skips nonexistent Gregorian occurrences rather than manufacturing a wall time. Ambiguous recurrence times retain the explicit series policy.

Phase-four planned dates remain compatible mirrors of task scheduling. Date commands update the planning anchors; applying a dependency preview updates valid calendar spans, date revisions and start reminders. A partial/zero-duration plan remains planning metadata and does not create a fake calendar span. All-day flags survive a propagated change only when the new endpoints still land on local midnights. Actual start/finish remains transition-history truth.

The Gregorian RRULE profile explicitly supports DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, weekly BYDAY/WKST, single positive BYMONTHDAY/BYMONTH, COUNT and UTC UNTIL. Unsupported combinations/parts fail with a stable domain error; this is not a claim to implement every RFC5545 rule part. Monthly skip is the default; last_day is an explicit product extension. Jalali month/year arithmetic is a separate ICU Persian calendar path, not Gregorian month arithmetic with Persian formatting. Its input anchor is a Gregorian local wall timestamp, with `calendar_system=jalali` controlling recurrence semantics. Holidays use the host's immutable versioned WorkingCalendar reference. Expansion is bounded to a 366-day request and 1000 returned items, with a finite historical scan. Weekly anchor defaults to Saturday. Source master tasks remain distinct from generated tasks.

Series template data pins title/description/priority/type and workflow revision. Creating generated tasks never clones grants, assignees, files or comments. A project workflow changing incompatibly requires explicit resolution rather than silently changing the pinned series workflow. Exceptions preserve original occurrence identity; completed occurrences survive rule changes. Future unfinished occurrences can be invalidated and restored using the same occurrence identity. After-completion mode waits for a real Done and creates at most one follow-up per invocation.

Source: [RFC5545 recurrence](https://www.rfc-editor.org/rfc/rfc5545#section-3.3.10), [PHP IntlCalendar factory](https://www.php.net/manual/en/intlcalendar.createinstance.php), [ICU calendar services](https://unicode-org.github.io/icu/userguide/datetime/calendar/). ext-intl is required when Jalali is used; core Todo installation does not require optional UI/calendar packages.

## Reminders and delivery

Reminder state `sent` means a notification intent was committed to the outbox, not that an email/SMS reached a customer. `(reminder_id,generation)` is unique. Anchor changes refresh generations in bounded chunks; unchanged anchors preserve snooze/sent state. Completion/archive/delete cancels task reminders. Notification delivery rechecks current reminder generation; stale queued intents are suppressed. Stage SLA notifications recheck whether the visit is still open.

EventPump uses actor/scope-bound durable subscriptions and separate delivery receipts. It refuses execution inside an open transaction. Consumers execute outside the claim transaction with a 30-second lease and a token-guarded acknowledgment. Five attempts use 5/30/120/600/3600-second delays; quiet-hour deferrals do not spend attempts. Delivery is at least once: host adapters must deduplicate event ID + recipient/channel or their own business operation. An effect followed by a crash before acknowledgment can be retried; no fake distributed exactly-once guarantee is made.

Built-in registered consumers are `notifications`, `automation`, and `webhooks` (the latter queues delivery). Hosts may register trusted boot-time callbacks; database values can select registered names but cannot instantiate arbitrary PHP or execute code. Every callback receives the explicit actor/scope and must retain domain authorization. Unsupported event schemas produce visible dead letters while the outbox record survives. The legacy single-consumer OutboxDispatcher remains compatible; advanced fan-out/retry uses EventPump receipts and its own offsets. Do not treat operational worker offsets as an end-user pagination API.

Default notification delivery and secret vault fail closed until the host binds implementations. There is no ambient Auth or unlimited system actor. Background entry points require an explicit service context with current actor-scoped capabilities.

## Automation

Rule revisions pin conditions, actions and the publishing actor's capabilities. Effective execution capabilities are the intersection of the worker's current capabilities and that revision. Conditions are fixed-field equals/in checks; action names and argument keys are whitelisted. Actions call existing versioned guarded services. Root event lineage is persisted for both generic and legacy Task producers. A root chain gets at most 20 actions; per-rule depth/action/hourly bounds also apply. The `(rule,event,action_key)` reservation survives retry. Rejected actions have durable reason codes and audit events; private exception text is not recorded. Rule enable/disable is versioned and retains the definition revision.

## Webhook boundary

Endpoint URL must be HTTPS, port 443, without URL credentials/fragment/control characters. DNS answers are all checked; mixed public/private responses reject. Private, loopback, metadata, mapped/transition and reserved address ranges reject under a deliberately conservative public-address policy. Optional exact host allowlists narrow access further. DNS is revalidated per attempt, and cURL pins the chosen address while retaining certificate/hostname verification. Proxy use and redirect following are disabled. The default HTTP transfer has a 3-second connection timeout, 10-second total transfer timeout and 64-KiB response-body limit. DNS lookup uses the system resolver; hosts requiring tighter resolver deadlines should bind DnsResolver. Literal IPv6 endpoint URLs are not accepted; validated AAAA answers for a hostname are supported.

The body contains only allowlisted metadata, schema version, scope and event identity. Handoff events also revalidate both endpoint subjects. Permission is checked again after DNS resolution. SecretVault resolves a scoped reference; the secret never enters audit/outbox/journal results. HMAC-SHA256 covers `timestamp.event_id.exact_body`. Incoming verification requires matching scope/schema, canonical lowercase UUID, a five-minute timestamp window and a unique receipt. Redirects never trigger a second request. Delivery attempts/backoff/dead letters and versioned manual retry are queryable. No real network delivery was performed in phase-five tests.

Sources: [cURL address pinning](https://curl.se/libcurl/c/CURLOPT_RESOLVE.html), [OWASP SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).

## Query, export and report truth

Normalization version 2 folds Persian/Arabic letters/digits and whitespace/ZWNJ; ext-intl adds Unicode compatibility normalization. Original titles remain intact. Existing rows are backfilled in bounded migration chunks. Reindex is scoped, bounded and gated by migration.manage. Typed numeric values use signed integer millionths; dates/booleans/keys have indexed typed columns, and multiselect has an indexed pivot. Archived fields retain values but are excluded from new forms. Host read capability checks apply before forms/filter/sort, not after paging.

Queries authorize the root SQL before counts/filter/sort/pages. Opaque server-side cursors bind actor, scope, canonical query/sort/limit, permission fingerprint and a 15-minute expiry. Package permission mutations advance the visibility epoch; hosts with external ACL revisions can bind AuthorizationRevision. Fresh SQL authorization always applies. Expired cursor cleanup is bounded; at most 1000 stored cursor records per scope/actor are allowed. Two 100-row pages require at most 13 SQL queries including cursor bookkeeping, independent of the fixture's 10k/100k size. The scale check measures PHP allocation delta, not total database RSS or release load capacity.

Export streams read authorized batches of 100. CSV cells beginning with formula/control prefixes are escaped, while JSON preserves data. Async artifacts use private application storage, opaque random references, expiry and a lease. Permission is checked at enqueue/build/download, including every recorded source ID; external host ACL revocation is checked even without a host authorization-revision binding. Download returns a freshly authorized stream, never a public presigned URL. A previously streamed byte cannot be recalled; the streaming contract reauthorizes each SQL batch. Group closure exports include permitted historical operation items for the selected group, rather than asserting a single latest run.

Reports label workflow category separately from process lifecycle and use typed transition history for as-of categories. Legacy unknown categories stay unknown. Elapsed dwell and paused time are defined separately; this report does not label elapsed dwell as business-clock time. Source fingerprints, clock time, authorization fingerprints and persisted permitted-instance membership invalidate cached metrics. Historical/current reports and command replay both check current source visibility. Rebuild stores membership using INSERT SELECT, not a full PHP ID array. Workload output is bounded to 1000 actors and fails explicitly beyond that bound. These are scoped backend reports, not installed-host/UI acceptance.
